# Prompt: CRM real por roles

Objetivo:
Diseña y ajusta un CRM funcional y operativo para tres perfiles: Administrador, Supervisor y Asesor. Todo debe responder a un flujo de trabajo real de atención comercial, seguimiento y control, sin módulos innecesarios ni pantallas de demostración.

## Rol 1: Administrador
Debe ver y controlar todo lo que hace el negocio.

Pantallas esenciales:
- Dashboard ejecutivo
- Inbox / bandeja de conversaciones
- Contactos y clientes
- Tareas y seguimiento
- Pipeline / oportunidades
- Ventas y cierre
- Alertas críticas
- Reportes de rendimiento
- Actividad del equipo
- Gestión de fallos / errores de integración
- Configuración de automatización / bot
- Conexiones de canales
- Gestión de usuarios y permisos

Flujo real:
1. Revisar dashboard general
2. Confirmar atención de conversaciones
3. Revisar oportunidades y ventas
4. Controlar tareas pendientes y alerta de fallos
5. Revisar rendimiento del equipo y reportes
6. Administrar usuarios, canales y permisos

## Rol 2: Supervisor
Debe vigilar ejecución, rendimiento y atención sin manejar la operación técnica completa.

Pantallas esenciales:
- Dashboard de equipo
- Inbox para revisar trabajo asignado
- Contactos
- Tareas y pendientes
- Pipeline con asesores
- Ventas del equipo
- Alertas operativas
- Reportes de productividad
- Actividad y carga por asesor

Flujo real:
1. Revisar tablero de desempeño
2. Ver cola de conversaciones y tareas
3. Validar asignaciones por asesor
4. Revisar oportunidades abiertas y cierre
5. Identificar atenciones atrasadas o riesgos
6. Generar reportes para seguimiento

## Rol 3: Asesor
Debe trabajar solo con lo necesario para atender clientes, vender y cerrar.

Pantallas esenciales:
- Dashboard personal / Mi trabajo
- Inbox asignada
- Contactos
- Tareas pendientes
- Pipeline personal
- Ventas y oportunidades

Flujo real:
1. Revisar conversaciones pendientes
2. Atender clientes y registrar notas
3. Resolver tareas y seguimientos
4. Gestionar oportunidades
5. Cerrar ventas y actualizar estado
6. Revisar su carga personal

## Principios de diseño
- El CRM debe sentirse real, operativo y útil para el día a día.
- El usuario no debe ver módulos que no forman parte de su trabajo.
- Cada rol debe tener una vista con prioridad, no un menú saturado.
- Las pantallas deben estar centradas en atención, seguimiento, ventas y control.
- Los paneles deben mostrar métricas, cargas, tareas y riesgos, no solo texto plano.
- El flujo de asesor debe arrancar en la bandeja, no en un panel general.
- El flujo de administrador y supervisor debe arrancar en dashboard ejecutivo.

## Restricciones de implementación
- Mantener solo los módulos esenciales por rol.
- No incluir módulos de prueba, diseño conceptual o funciones no operativas.
- Usar nombres y acciones que reflejen el uso real del CRM.
- Priorizar claridad, rapidez y control de trabajo.
- Si un módulo no aporta al trabajo diario del rol, eliminarlo o ocultarlo.

## Resultado esperado
Un CRM limpio, entendible, funcional y muy cercano a la operación real de un negocio con atención comercial, supervisión y ventas.
